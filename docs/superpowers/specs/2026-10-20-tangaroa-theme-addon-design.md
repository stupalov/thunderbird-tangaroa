# Tangaroa для Thunderbird: тема-дополнение со светлым и тёмным вариантом

Дата: 2026-10-20. Статус: утверждён пользователем 2026-10-20.

## Зачем

Postbox больше не развивается. Пользователь остаётся в Thunderbird и хочет
максимально точно воспроизвести оформление Postbox с темой Tangaroa. Сейчас
это делает userChrome-комплект (репозиторий thunderbird-tangaroa 0.1.0):
копирование `chrome/` и `user.js` в профиль, ручные шаги, только светлый вид.
Проверка на Windows показала, что при тёмном режиме системы светлый комплект
не сочетается с тёмной темой Thunderbird (нечитаемый заголовок письма).

Цель — превратить комплект в **настоящую тему Thunderbird**, которая
ставится и переключается как в Postbox: один XPI, «Дополнения и темы → Темы»,
никакого копирования файлов и никаких ручных настроек. Тема несёт светлый
вариант (Tangaroa как есть) и тёмный вариант (на основе Postbox Midnight с
ключевыми цветами Tangaroa) и сама следует системному режиму.

## Цели

- Один файл `tangaroa-<версия>.xpi`, устанавливается через штатный менеджер
  дополнений, виден в разделе «Темы», включается и выключается там же.
- Светлый вариант воспроизводит текущий вид Tangaroa (палитра экспорта
  Postbox `Tangaroa.json`, структура из `chrome/postbird/*`).
- Тёмный вариант: структура и подход Postbox Midnight (`Midnight.json`), но
  ключевые цвета Tangaroa: акцент выделения `#55ADF8`, бейджи `#dd491a`,
  опорный синий боковой панели `#1E2D3F`. Остальные тона выведены из этого
  синего, а не из почти чёрного Midnight.
- Переключение светлый/тёмный автоматическое по системной теме, без действий
  пользователя (ключ `dark_theme` манифеста).
- Текст и элементы читаемы в обоих вариантах на macOS и Windows; заголовок
  письма, меню, поля ввода, кнопки получают цвета темы, а не остатки
  системной светлой/тёмной темы Thunderbird (`properties.color_scheme`).
- AccountPane работает поверх темы без изменений: он читает штатные
  переменные боковой панели (`--sidebar-*`, `--list-container-*`,
  `--folderpane-*-count-*`, `--treeitem-*`), и тема задаёт именно их.
- Никаких сетевых запросов, телеметрии, скриптов. Лицензия MIT, атрибуция
  Postbird сохраняется.

## Не цели

- Не задавать настройки профиля (`mail.uifontsize`, `mail.uidensity`,
  `mail.threadpane.listview`, `mail.pane_config.dynamic`, шрифты писем).
  Статическая тема этого не умеет; по решению пользователя эти настройки
  **не применяются вообще** и не требуются. Тема должна выглядеть правильно
  при настройках по умолчанию: и в табличном виде, и в виде карточек, при
  любой плотности. Высота строк списка не принуждается через CSS.
- Не переключать тему принудительно вручную «светлая/тёмная» внутри темы:
  это делает система и Thunderbird. Если пользователь хочет всегда тёмную,
  он включает тёмный режим системы (в Thunderbird нет настроек у тем).
- Не оформлять окно создания письма, адресную книгу, календарь и чат сверх
  того, что дают стандартные цветовые ключи темы (`frame`, `toolbar`,
  `popup`, `sidebar`, поля ввода). Отдельный CSS для них в этой версии не
  пишется.
- Не публиковать в каталоге дополнений Thunderbird (ATN) в рамках этой
  работы; только GitHub-релиз. Требования ATN к theme_experiment
  проверяются отдельно.
- Не поддерживать Thunderbird старше 157.

## Антицели (что сделает работу провальной)

- Тема, которая требует копирования файлов или правки `about:config`.
- Тёмный вариант, похожий на Midnight, но потерявший синий характер и
  оранжевые бейджи Tangaroa.
- Нечитаемые области (как заголовок письма при тёмной системе на Windows).
- Сломанная прокрутка или «пляшущие» строки списка из-за принудительной
  высоты строк.
- Любые изменения в поведении AccountPane или конфликт с ним.

## Ограничения

- Thunderbird 157.0 и новее, `strict_max_version: "*"` (как у AccountPane).
- Только статическая тема: `manifest.json` с `theme`, `dark_theme`,
  `theme_experiment`. Никакого `background`, никаких разрешений.
  `theme_experiment` поддерживается Thunderbird с версии 86 и не требует
  включения экспериментов.
- Репозиторий: `thunderbird-tangaroa` (GitHub, приватный). userChrome-комплект
  0.1.0 остаётся в истории и в релизе v0.1.0; в рабочем дереве его заменяет
  тема. README переписывается под новый способ установки (англ. + рус.).
- Проверка: рабочий профиль пользователя на macOS (Thunderbird 158) и
  тестовый профиль в Windows 11 VM (Thunderbird 158, клавиатурный стенд
  `prlctl`, см. HANDOFF AccountPane). Эталон — окна Postbox на Mac с темами
  Tangaroa и Midnight (снимки лежат локально, в Git не попадают: там реальная
  почта).
- Сборка и тесты без npm-зависимостей: `python3 scripts/build.py`, 
  `node --test tests/*.test.mjs`, воспроизводимый ZIP с SHA-256.

## Как это устроено (решения)

### Манифест

```json
{
  "manifest_version": 2,
  "name": "Tangaroa",
  "description": "Postbox Tangaroa appearance for Thunderbird, light and dark.",
  "version": "0.2.0",
  "browser_specific_settings": {
    "gecko": { "id": "tangaroa@stupalov.github.io",
               "strict_min_version": "157.0", "strict_max_version": "*" }
  },
  "icons": { "32": "icons/tangaroa-32.png", "48": "icons/tangaroa-48.png", "64": "icons/tangaroa-64.png" },
  "theme": { "colors": { ...светлая палитра... },
             "properties": { "color_scheme": "light", "content_color_scheme": "light" } },
  "dark_theme": { "colors": { ...тёмная палитра... },
                  "properties": { "color_scheme": "dark", "content_color_scheme": "dark" } },
  "theme_experiment": {
    "stylesheet": "tangaroa.css",
    "colors": { "tg_bg_primary": "--tg-bg-primary", "tg_bg_sidebar": "--tg-bg-sidebar", ... },
    "properties": { "tg_row_divider_style": "--tg-row-divider-style" }
  }
}
```

- Стандартные ключи `theme.colors` (`frame`, `toolbar`, `toolbar_text`,
  `toolbar_field*`, `tab_*`, `sidebar*`, `popup*`, `icons`,
  `button_background_*`) заполняются из той же палитры, чтобы меню, поля,
  вкладки и окна без нашего CSS выглядели согласованно.
- Собственные ключи `tg_*` через `theme_experiment.colors` отображаются в
  CSS-переменные `--tg-*`, которые объявляет `tangaroa.css`. Оба варианта
  (`theme` и `dark_theme`) задают **один и тот же набор** ключей; тест
  проверяет, что множества совпадают.
- Числовые токены (размеры, отступы, радиусы) не зависят от варианта и
  живут в `tangaroa.css` как обычные переменные.

### Стиль `tangaroa.css`

Перенос `chrome/postbird/components/*.css` и `config.css` в один файл с
переименованием `--pb-*` → `--tg-*`, без `@-moz-document` (стиль
theme_experiment применяется ко всем chrome-документам, включая
`about:3pane` и `about:message`; строитель проверяет это первым спайком, см.
ниже). Области: unified toolbar и подписи кнопок, цвета иконок действий,
вкладки, рельса Spaces, панель папок (включая переменные, которые читает
AccountPane), список писем в табличном виде **и** в виде карточек, заголовок
письма и рамка области чтения, панель быстрого фильтра, строка состояния.

Типографика: `system-ui` как семейство (San Francisco на macOS, Segoe UI на
Windows), размеры как в комплекте 0.1.0 (список 13 px, разделы 11 px,
заголовок письма 12 px, тема 18 px, подписи кнопок 11 px). Высота строк не
задаётся.

### Палитры

Светлая — экспорт Postbox Tangaroa, значения без изменений (уже в
`config.css`). Тёмная — моё предложение, уточняется по снимкам при сборке:

| Токен | Светлая (Tangaroa) | Тёмная (Tangaroa Midnight) |
|---|---|---|
| bg-primary (список, чтение) | `#F9FAFC` | `#16222F` |
| bg-secondary / chrome | `#E5E9F2` | `#1A2838` |
| bg-sidebar | `#1E2D3F` | `#1E2D3F` |
| toolbar top → bottom | `#E2E7EE` → `#C5D0DD` | `#253649` → `#1A2838` |
| tab active / inactive | `#CBD4E0` / `#B9C5D2` | `#1E2D3F` / `#172330` |
| divider dark / light | `#adb8c4` / `#D2D8E6` | `#34455A` / `#2C3B4E` |
| selector / selector-sidebar | `#55ADF8` | `#55ADF8` |
| selector-inactive | `rgba(192,204,218,.6)` | `rgba(255,255,255,.12)` |
| selector-thread-inactive | `#E4E9F3` | `rgba(255,255,255,.08)` |
| font-primary / secondary | `#1E2D3F` / `#5E6C79` | `rgba(255,255,255,.95)` / `#8494A3` |
| font sidebar primary / secondary | `#F9FAFC` / `#8494A3` | `#F9FAFC` / `#8494A3` |

| text-field bg / border | `#FFFFFF` / `#DFE3E7` | `rgba(255,255,255,.10)` / transparent |

Принцип тёмного варианта: все нейтральные фоны — оттенки того же синего, что
`#1E2D3F` (hue ≈ 213°), светлее к панели инструментов и темнее к списку;
Midnight задаёт только роли (что светлее чего, прозрачности текста и
выделений).

### Репозиторий после работы

```
thunderbird-tangaroa/
├── theme/                 manifest.json, tangaroa.css, icons/, LICENSE-Postbird
├── scripts/build.py       воспроизводимый XPI в dist/
├── scripts/render-icons.mjs (опционально, как в AccountPane)
├── tests/*.test.mjs       манифест, паритет ключей, переменные, сборка
├── docs/                  development.md, testing.md, images/ (превью)
├── README.md, README.ru.md, CHANGELOG.md, ATTRIBUTION.md, LICENSE
```

`chrome/` и `settings/` удаляются из рабочего дерева (остаются в теге
v0.1.0). В README: раздел «Установка» = скачать XPI → Дополнения и темы →
Установить дополнение из файла; «Светлый и тёмный» = следует системе;
примечание, что табличный вид, плотность и классическое расположение
выбираются штатно по вкусу и для темы не обязательны.

## Решения по вопросам проверяющего (мои решения, если не сказано иное)

- **Каскад и `!important`.** Стиль theme_experiment — обычный chrome-стиль;
  `!important` на переменных и правилах допустим и ожидаем, как в 0.1.0.
  Тема задаёт штатные переменные Thunderbird на контейнерах (`#folderPane`,
  `#threadPane` и т. п.) и собственные `--tg-*` на `:root`. AccountPane не
  меняется ни при каком исходе; если какая-то переменная до него не доходит,
  это дефект темы, а не повод править расширение.
- **Доступные селекторы.** Строки списка, заголовки колонок, дерево папок и
  заголовок письма — обычный DOM внутри `about:3pane`/`about:message`;
  shadow DOM (например, внутренности `unified-toolbar-button`) не трогаем.
  Область, недостижимая стилем темы, пропускается и фиксируется в
  `docs/testing.md`; второй механизм (userContent, Experiment) не вводится.
- **Режимы.** Поддерживается только системный режим: «система светлая» и
  «система тёмная». Собственные переопределения Thunderbird
  (`browser.theme.toolbar-theme`, `layout.css.prefers-color-scheme.content-override`)
  не поддерживаются и не тестируются; матрица проверки — 2 режима × macOS и
  Windows.
- **Критерий тёмной палитры.** Эталон — снимки Postbox Midnight и Tangaroa,
  которые сверяю я (автор) при сборке; значения из `Tangaroa.json` и
  `Midnight.json` кладутся в `docs/reference/postbox-palettes.json` (только
  имена и значения переменных, с указанием источника). Минимальный критерий
  для текста — контраст не ниже 4.5:1 на своих фонах.
- **Иконки действий** в тёмном варианте — отдельные ключи `tg_icon_*`,
  заданные в обоих вариантах (паритет ключей), значения по умолчанию те же,
  что в светлом.
- **Иконка темы** рисуется заново (SVG → PNG скриптом, как в AccountPane):
  две горизонтальные плашки цветов Tangaroa; лицензия MIT, без материалов
  Postbox.
- **Windows** проверяется обязательно перед релизом: стенд с `prlctl` уже
  есть (см. HANDOFF AccountPane); релиз v0.2.0 выходит только после проверки
  обоих режимов на macOS и Windows.
- **Запасные планы при провале спайка.** Решение пользователя: при провале
  (а) или (б) строитель останавливается и спрашивает пользователя; запасной
  план не принимается самостоятельно.

## Что оставлено строителю

- Точные селекторы Thunderbird 157–158 для карточного вида и заголовка
  письма; подбор контраста в тёмном варианте по снимкам; что именно из
  `theme.colors` нужно задать, чтобы меню и поля в тёмном варианте не
  оставались системными.
- **Спайк в начале:** минимальная тема с `theme_experiment.stylesheet`,
  красящая `#folderPane` и `#threadTree`, установленная в тестовый профиль
  (macOS или Windows VM). Проверить: (а) стиль применяется внутри
  `about:3pane`/`about:message`; (б) `dark_theme` действительно включается при
  тёмной системе на 158. Если (а) не работает, стиль остаётся только для
  `messenger.xhtml`; запасной план по решению пользователя (см. вопрос
  ниже). Если (б) не работает, запасной план — две темы в двух XPI
  («Tangaroa» и «Tangaroa Midnight»), выбор пользователь делает в менеджере
  тем вручную; это тоже решение пользователя.

При провале (а) или (б) строитель останавливается и ждёт решения
пользователя (утверждено).
- Порядок переноса CSS, набор тестов, превью для README (по образцу
  AccountPane: браузерный рендер с вымышленными данными, не снимки реальной
  почты).
